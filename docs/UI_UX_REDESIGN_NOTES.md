# UI/UX Redesign Notes (CaseFlow AI Frontend)

## 目标
- 让用户在 10 秒内理解产品主路径：收件 → AI 预审 → 人工审批。
- 把“AI 不是律师、外部动作需人工审批”的边界前置，而不是埋在细节里。
- 减少首页和列表页的信息噪音，提升可决策性。

## 当前产品合理性判断
1. 这是审查工作流，不是问答机器人。
2. 用户核心任务是“推进案件”，不是“浏览信息”。
3. 风险控制优先级高于视觉炫技：证据可追溯、状态可解释、动作可审计。

## 这次改动做了什么
1. 信息架构重排
   - 首页改为“主路径 + 边界 + 下一步”。
   - 案件列表页强调“分诊”而不是堆数据。
   - 审批队列页强化“最后安全阀”定位。

2. 文案语言统一
   - 主要页面和核心组件改为中文语义（保留必要英文术语）。
   - 状态文案更贴近审查场景（待审批、需修改、待核对等）。

3. 风险边界显性化
   - 首页新增“产品边界”卡片组。
   - 页头/页脚持续提示人工审批要求。

4. 视觉与交互细节
   - 增加 journey/principles 卡片样式，提升结构化阅读效率。
   - 保持当前 CSS 架构，做增量优化以降低重构风险。

## 后续建议（下一轮）
1. 在案件列表加入可排序字段（风险级别、交割日期、待办数）。
2. 在案件详情加入“证据完整度分数 + 快速定位到文档页”的交互。
3. 审批队列支持批量操作与 SLA 提醒。
4. 统一中英文文案字典，避免局部页面语言混杂。
5. 增加前端自动化测试（Playwright）覆盖主路径。
